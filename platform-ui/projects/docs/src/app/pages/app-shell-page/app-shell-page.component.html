Grouped vs flat navigation — navGroups vs navItems

sidebarGroups accepts two shapes. Pass an array of SolifiNavGroup objects (each with its own id, label, and items) to get a section label above every cluster — that's what "navGroups" means. If you don't want section labels at all, skip the group wrapper and pass a plain SolifiNavItem[] array instead — commonly called "navItems". The shell checks whether the first array element has an items key: if it doesn't, the whole array is treated as one flat, ungrouped list and no label renders above it. Same [sidebarGroups] input either way — nothing else in your template changes.

Understanding Every Input & Output

Every pui-lib-app-shell property, grouped by what it controls — sidebarX only ever touches the left nav rail, headerX only ever touches the top bar. Expand a category to read its explanation — nothing is mixed together.

Framework Usage

Use pui-lib-app-shell as your application's root layout — it owns the sidebar, collapse behaviour, user profile, and theme. Drop your page content (e.g. <router-outlet />) directly inside it via ng-content / children. Every input name tells you which part of the shell it affects: sidebarX for the left nav rail, headerX for the top bar — nothing unprefixed except the two shell-level layout props, pageTitle and footerText.
